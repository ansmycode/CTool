# Wolf 多游戏语义映射

## 原则与当前实现

2026-09-14：分类改为独立标签页，每类完整滚动表、搜索与虚拟渲染；无界面分页，底层仍按 10 行限额分批读取，只刷新活动分类。提示压缩为工具栏及悬停说明。

修复库存行数缓存问题：Nemoriar 初始道具数量表 10 行，旧代码对 start >= 10 的批次直接跳过读取。现在查询运行时总行数再取对应批次；运行时扩容不再被初始行数阻止。未实际分配的记录显示“未建记录”，结构不符/读取失败与映射未确认分别说明，不擅自补 0。新增合成回归覆盖运行时 10→25 行、真实缺失与读取失败；不等于已验证该游戏所有道具数量。

适配分为三层：原生内存布局读取 → Wolf 数据语义映射 → 独立能力页面。布局兼容不代表业务语义兼容，游戏版本/文件哈希/表编号均不作为语义选择规则。

- 原始数据库与连接诊断仅在 DEV UI 加载，普通版本不显示表/字段编号及手动金币来源绑定；删除每个数字旁的“设为金币”。
- 现有金币双向链路保留，用户已验收成功。
- 新增物品资料：独立列出道具、武器、防具或合并装备类别，按字段类型读取名称、说明，不强行套 MV/MZ 全部功能。
- 同命名空间、唯一的定义表和数量表配对；基本系统队伍证据存在时可采用同记录 ID 的只读库存规则。其他分组标记候选，不自动当成当前背包。
- 空白和分隔行不展示，但保留真实记录 ID。缺失/非法数量为未知，不能补 0；数据页定时刷新，失败清除旧内容。
- 当前不开启库存、装备或角色写入；基本系统规则仍需要更多真实游戏验证，不宣称任意自定义系统通用。

## 规则扩展而非游戏特判

规则入口 src/engine/wolf/databaseMapping.js；支持日/中/英常用表名与字段别名、同组隔离、唯一性和类型约束。新变体须补独立结构夹具与真实行为证据；自定义命名、ID 字段关联、稀疏库存、堆栈库存等通过新增独立规则支持，禁止直接填入某游戏的表编号。

后续库存写入必须独立设计：确认 ID 关系、数量上限、缺失记录创建策略、读档/切场景的安全时机、菜单刷新和回读。不能复用金币写命令绕过这些边界。

## 其他引擎隔离

只有 Wolf adapter 提供可选 collections 接口。MV/MZ adapter、HTTP 服务和注入脚本本轮不修改；不增加虚假 overview/items 能力，不改变既有 MV/MZ 标签页和动作。公共外壳只在有 collections 接口时增添页面。

验证：npm run build、npm run test:wolf（重排编号/字段、多命名空间、歧义、错误类型、翻译字段）、npm run test:injection。真实多游戏兼容需持续积累，当前样本不能替代其他版本验证。
