## 0. 完成情况

AI 翻译第一版已经完成并接入现有翻译工具，当前实现范围如下：

- 已接入 OpenAI Responses API 和 DeepSeek Chat Completions API，当前开放 OpenAI 与 DeepSeek 服务商。
- 已提供 API 地址、API Key、模型、源语言和目标语言配置，以及真实连接测试。
- 默认每批最多 `100` 条、`12000` 字符，并发数为 `1`；批量请求之间至少间隔 `1000ms`。
- 支持服务商 `Retry-After`、有限重试，以及格式异常或批次过大时自动减半重试。
- 工作文件在首次开始翻译时创建，每批成功后原子保存；意外关闭后可重新选择原始 JSON 继续。
- 同一文件同时只允许一个翻译任务，避免重复调用和工作文件竞争。
- 全部完成后输出纯净翻译 JSON，第一版继续保留工作文件，不自动删除。
- 已完成模拟接口、工作文件、分批、重试、任务锁和构建测试；真实接口功能已由人工跑通。

Kimi、自定义兼容接口、暂停、实时进度、费用估算和自定义提示词不属于当前已完成范围，后续按实际需要决定是否增加。

## 1. 功能目标

CTool 已经可以提取适合翻译的纯净文本，并生成键值形式的 JSON。AI 翻译功能只负责完成下面这条链路：

```text
选择翻译 JSON
  → 设置 AI 服务商、API Key、模型和语言
  → 自动载入或创建同目录工作文件
  → 将工作文件中未处理的内容分批发送给 AI
  → 合并每批结果并更新工作文件
  → 输出纯净翻译 JSON
  → 交给现有实时加载或内嵌翻译功能使用
```

第一版不对标 MTool 的全部能力，不重新设计文本提取流程，也不建立复杂的翻译项目缓存。核心目标是简单、可靠地跑通 AI 批量翻译。

## 2. 已确定的设计

1. AI 请求使用用户自己的 API Key。
2. 内置 OpenAI、DeepSeek、Kimi 等常用服务商；选择后自动填写官方 API 地址。
3. 额外提供“自定义”服务商，允许用户自行填写中转站或其他兼容接口地址。
4. 第一版只适配并测试 2～3 个模型，不追求一次支持所有模型。
5. 源语言和目标语言完全由用户设置，不做自动识别。
6. 输入只使用 CTool 已经提取出的 JSON，不重新扫描游戏数据。
7. 使用单独的工作文件和 `status` 记录处理状态；已翻译和已跳过结果直接保留。
8. 工作文件和最终翻译文件都输出到用户所选原始 JSON 的目录。
9. 不提供费用估算，用户在对应 AI 厂商的开发者平台查看实际消费。
10. 第一版不提供自定义系统提示词。
11. AI 翻译作为 `TranslateTool` 中的下级组件存在，不改变现有三个翻译功能按钮的层级。
12. 第一版不提供暂停、中止和实时进度展示，任务开始后锁定配置并等待执行结束。
13. 工作文件在首次点击“开始翻译”时创建；仅选择原始 JSON 不产生工作文件。
14. 工作文件作为断点恢复和增量翻译依据，即使全部完成并成功导出纯净 JSON 后也继续保留，第一版不自动删除。
15. 分批大小和请求并发数相互独立；第一版默认每批最多 `100` 条、`12000` 字符，并发数保持为 `1`，请求之间至少间隔 `1000ms`。

## 3. 原始文件、工作文件与最终文件

### 3.1 原始文件

用户选择的仍是 CTool 已经提取出的纯净 `原文: 译文` JSON：

```json
{
  "New Game": "New Game",
  "Continue": "继续游戏",
  "Exit": "Exit"
}
```

首次创建工作文件时：

- value 与 key 相同：创建为 `status: untranslated`。
- value 与 key 不同且不是空字符串：作为已有译文导入，并设置为 `status: translated`。
- value 为空或不是字符串：记录为待处理异常项。

### 3.2 工作文件

处理阶段不要求保持纯净键值格式，可以增加状态字段。推荐使用以原文为索引的结构，方便快速查找和增量合并：

```json
{
  "version": 1,
  "source": {
    "fileName": "CatToolTranslate.json",
    "fingerprint": "原始文件内容摘要"
  },
  "items": {
    "New Game": {
      "value": "新游戏",
      "status": "translated"
    },
    "Continue": {
      "value": "Continue",
      "status": "untranslated"
    },
    "123": {
      "value": "123",
      "status": "skipped"
    },
    "Broken entry": {
      "value": "Broken entry",
      "status": "error",
      "error": "返回结果中缺少该项目"
    }
  }
}
```

持久化状态只保留四种：

- `untranslated`：尚未处理，需要发送给 AI。
- `translated`：AI 或用户已经给出译文，续传时直接保留。
- `skipped`：AI 判断无需翻译，value 可以保持原文，续传时直接保留。
- `error`：由于非法响应、缺项或其他未知原因未能完成，允许重试。

“正在翻译”只作为界面运行状态存在，不写入工作文件。一批请求返回后，工具逐项校验：有效项更新为 `translated` 或 `skipped`，无效项更新为 `error`，然后一次性原子保存工作文件。如果请求返回前程序崩溃，该批仍保持 `untranslated`，下次可以安全重试。

工作文件建议命名为：

```text
<原文件基础名>.ctool-ai-work.json
```

例如原文件是 `CatToolTranslate.json`，工作文件就是：

```text
CatToolTranslate.ctool-ai-work.json
```

### 3.3 发送给 AI 的批次

从工作文件中选择 `status: untranslated` 或需要重试的 `status: error` 项目，组成简单数组：

```json
[
  { "key": "New Game", "value": "New Game", "status": "untranslated" },
  { "key": "123", "value": "123", "status": "untranslated" }
]
```

要求 AI 保持 `key` 不变，只修改 `value` 和 `status`：正常翻译设为 `translated`；确认无需翻译时保持原 value，并设为 `skipped`。AI 无法确定时默认进行翻译，不要轻易跳过。

### 3.4 最终文件

当所有项目都是 `translated` 或 `skipped` 后，从工作文件剥离辅助字段，只输出纯净键值：

```json
{
  "New Game": "新游戏",
  "Continue": "继续游戏",
  "123": "123"
}
```

最终文件建议命名为 `<原文件基础名>.ai-translated.json`，与原始 JSON 放在同一个目录。第一版默认也输出 `skipped` 项，并保持 `key: key`，从而维持与原始文件一一对应；即使以后选择省略这些项，也不会影响游戏找不到译文时回退到原文。

## 4. 服务商与模型配置

第一版采用“厂商预设 + 自定义”的配置方式：

- OpenAI
- DeepSeek
- Kimi
- 自定义

预设项内置厂商名称、官方 API 地址和已经测试的模型。选择“自定义”时，由用户填写中转站地址和模型名称。第一版的自定义地址只支持项目已经实现的兼容协议，不承诺任意私有协议都能调用。

```ts
interface AIProviderPreset {
  id: string;
  name: string;
  baseUrl: string;
  editableUrl: boolean;
  models: Array<{
    id: string;
    name: string;
  }>;
}
```

界面提供：

- 服务商选择
- API 地址：预设厂商自动填写并允许手动修正；自定义服务商由用户输入
- API Key
- 模型选择，只列出第一版确认测试过的 2～3 个模型
- 源语言
- 目标语言
- 连接测试

服务商的官方接口地址通常不会频繁变化，使用内置默认值可以减少用户配置成本；如果以后发生变化，用户仍可手动修正。中转站用户直接选择“自定义”，避免把官方预设与第三方地址混在一起。

虽然第一版只测试少量模型，内部仍应将请求封装在统一接口中，避免以后增加服务商时重写整个翻译流程：

```ts
interface AITranslationEntry {
  key: string;
  value: string;
  status: "untranslated" | "translated" | "skipped" | "error";
}

interface AITranslationProvider {
  testConnection(config: AIConfig): Promise<void>;
  translate(
    entries: AITranslationEntry[],
    config: AIConfig,
    signal: AbortSignal
  ): Promise<AITranslationEntry[]>;
}
```

第一版可以只实现当前选定厂商需要的协议，不提前编写没有实际测试对象的适配器。

## 5. API Key 安全方案

CTool 是开源项目，但开源本身不能完全阻止 API Key 被窃取。主要风险不是项目作者主动收集 Key，而是：

- 用户下载了被第三方篡改的安装包。
- 依赖包或构建流程被植入恶意代码。
- API Key 被写入日志、配置文件或错误报告。
- 渲染进程中的脚本能够读取 Key。
- 用户把 Key 发送给错误或不安全的 API 地址。

### 5.1 第一版建议

第一版只在本次运行期间保存 API Key：

1. 用户在设置页输入 Key。
2. 通过专用 IPC 将 Key 交给 Electron 主进程。
3. 主进程只在内存中保存并发起请求。
4. 页面输入状态在提交后可以清空；关闭 CTool 后 Key 自动消失。
5. 不写入 JSON、`localStorage`、日志、任务文件或游戏目录。

这样比实现本机持久化更简单，也减少了最直接的泄漏面。用户每次启动重新输入 Key 是第一版可以接受的成本。

### 5.2 必须落实的安全要求

- API 请求只能由 Electron 主进程发起。
- preload 只暴露 AI 翻译需要的专用方法，不暴露任意 IPC 或网络请求能力。
- 保持 `contextIsolation: true` 和 `nodeIntegration: false`。
- Key 输入框默认隐藏，只允许用户主动临时显示。
- 所有日志和报错必须过滤 `Authorization`、API Key 和完整请求头。
- 不在开发者工具、通知或连接测试结果中回显完整 Key。
- 自定义地址默认要求 HTTPS；本机地址可以例外。HTTP 地址必须显示风险警告。
- 切换服务商或 API 地址时，要求用户重新确认 Key 的发送目标。
- 发布版本应由项目官方渠道提供校验信息，提醒用户不要运行来历不明的二次打包版本。
- 定期检查直接依赖，避免为了保存一个 Key 引入不必要的高权限依赖。

如果以后确实需要“记住 API Key”，再单独评估操作系统凭据存储。第一版不把 Key 明文保存在本机配置文件中。

## 6. 分批翻译

一个 JSON 可能包含几万条文本，不能一次全部发送。第一版使用简单的双重限制分批：

- 每批最大条目数
- 每批最大总字符数

组批时依次加入待翻译键值；达到任意一个限制后开始下一批。第一版不要求接入复杂 tokenizer，只需要为已测试模型设置足够保守的默认值。

```text
读取原始 JSON 与同目录工作文件
  → 增量合并两者
  → 筛选 untranslated 和需要重试的 error 项目
  → 按条目数和字符数分批
  → 串行请求 AI
  → 校验并合并
  → 每批保存工作文件
```

默认并发数为 `1`。先保证正确性和稳定性，后续确有速度需求再考虑有限并发。

单条文本如果超过本批字符上限，可以让它独占一个批次。由于输入已经经过 CTool 提取和清理，第一版不再进行文本分类、控制符替换、上下文定位或自动拆句。

AI 判断某项为数字、符号、代码、底层标识或其他无需翻译的内容时，应返回原 value，并将状态设置为 `skipped`，以后不再重复发送。

由于 AI 只看到纯净文本，没有文本在游戏文件中的来源位置，它无法绝对判断某段内容是否会展示给玩家。因此 `skipped` 只是一种兜底能力：只有明确无需翻译时才跳过，无法确认时默认翻译并返回 `translated`。

## 7. 固定提示词

第一版使用程序内置提示词，只注入用户选择的源语言和目标语言。提示词的职责只有：

1. 将每项 value 从源语言翻译成目标语言。
2. 保持所有 key 完全不变。
3. 正常翻译后将 status 设为 `translated`。
4. 明确无需翻译时保持 value 不变，并将 status 设为 `skipped`。
5. 无法判断是否需要翻译时，默认进行翻译，不要跳过。
6. 只返回合法 JSON，不添加 Markdown、说明或代码块。
7. 不遗漏、增加或合并条目。
8. 尽量保持游戏文本简洁自然。

示意：

```text
请将以下 JSON 数据的 value 从 {sourceLanguage} 翻译为
{targetLanguage}。所有 key 必须保持原样。正常翻译后将 status 设为
translated。只有确认内容无需翻译时，才保持 value 原样并将 status
设为 skipped；无法确认时默认翻译。
只返回合法 JSON，不要输出解释、Markdown 或其他内容。
```

第一版不允许用户修改系统提示词，避免自定义内容破坏返回格式。需要风格、术语表或上下文时，再在后续版本中迭代。

## 8. 工作文件匹配、返回校验与导出

### 8.1 用户再次选择原始 JSON

用户断点续传时仍然选择原始 JSON。工具根据原文件所在目录和文件名，自动计算对应的工作文件路径：

```text
原始：D:\Games\Example\CatToolTranslate.json
工作：D:\Games\Example\CatToolTranslate.ctool-ai-work.json
输出：D:\Games\Example\CatToolTranslate.ai-translated.json
```

如果工作文件不存在，就根据原始 JSON 创建。如果已经存在，则按原文 key 和工作状态重新合并，不能用原始 JSON 整体覆盖已经完成的结果。

合并规则：

1. 工作项为 `translated`：完整保留工作项的译文和状态，不被原始 JSON 覆盖。
2. 工作项为 `skipped`：完整保留原 value 和状态，不再发送给 AI。
3. 工作项为 `untranslated` 或 `error`：使用最新原始 JSON 的 value 重新生成；value 与 key 相同时设为 `untranslated`，已有译文时设为 `translated`。
4. 原始 JSON 出现新 key：按相同规则新增为 `untranslated` 或 `translated`。
5. 工作文件中的 key 已不在最新原始 JSON：从当前工作内容中移除，不写入最终输出。

这样重新选择原始文件不会覆盖 `translated` 和 `skipped`，而 `untranslated` 与 `error` 会按最新原文重新进入正常处理流程。

`fingerprint` 只用于提示原文件发生过变化，真正的续传匹配仍以原文 key 为准。

### 8.2 AI 返回校验

每批返回后只做必要检查：

- 能否解析成 JSON 对象
- 返回的 key 是否都属于本批原文
- 是否缺少 key 或出现额外 key
- value 是否为字符串
- key 是否被 AI 修改
- status 是否为 `translated` 或 `skipped`

通过校验的项目立即合并进工作文件。缺少、错误或无法解析的项目记录为 `error`，并保存简短错误原因；已经成功的 `translated` 和 `skipped` 项目不重复请求。`error` 由工具设置，AI 不允许主动返回该状态。

### 8.3 保存与最终导出

不需要额外的数据库或另一份缓存。工作 JSON 本身就是唯一的处理中间状态。每批成功后都更新工作文件；写入时先生成临时文件，再替换正式文件，避免中途退出导致整个 JSON 损坏。

当所有项目都已经是 `translated` 或 `skipped`，生成同目录的纯净翻译 JSON。只要仍存在 `untranslated` 或 `error`，任务就不能显示为完整完成，但可以保留工作文件继续重试。

原始输入文件和工作文件都不覆盖。输出完成后弹出明确提示：

```text
AI 翻译已完成，翻译文件已保存至：
<完整文件路径>

请在“加载翻译文件”功能中重新选择该文件。
```

第一版不自动把翻译文件加载进当前游戏，用户自行重新选择，可以让 AI 翻译与现有加载流程保持解耦。

## 9. 错误处理

第一版需要区分以下错误：

| 错误 | 处理方式 |
| --- | --- |
| API Key 无效 | 立即停止，提示用户检查 Key |
| API 地址或模型错误 | 立即停止，保留当前工作 JSON |
| 余额不足或没有权限 | 立即停止，交由用户前往厂商平台处理 |
| 请求超时或临时网络错误 | 自动重试有限次数 |
| 请求过于频繁 | 等待后重试 |
| 返回内容不是 JSON | 重试当前批次 |
| 返回缺少部分 key | 保存有效项，只重试缺少项 |
重试必须设置上限，不能无限调用 API。错误提示中不得包含 API Key。

## 10. 第一版界面

### 10.1 功能层级

现有 `TranslateTool` 的三个按钮保持不变：

```text
翻译工具
├─ 加载翻译文件
├─ 提取文本
├─ 自动内嵌文本
└─ AI 翻译
   ├─ 选择原始 JSON
   ├─ 配置 AI
   ├─ 开始翻译
   └─ 翻译结束后显示结果
```

AI 翻译负责生成翻译文件，生成后仍然通过上层已有的“加载翻译文件”按钮交给游戏使用。因此不把现有功能拆分为“常规翻译”和“AI 翻译”两个页面，也不增加内层 Tabs。

组件结构建议：

```tsx
<TranslateTool>
  <Space>
    {/* 加载翻译文件、提取文本、自动内嵌文本 */}
  </Space>

  <AITranslation />

  {/* 已有的文本提取与内嵌提示组件 */}
</TranslateTool>
```

视觉布局：

```text
┌──────────────────────────────────────────────┐
│ [加载翻译文件] [提取文本] [自动内嵌文本]      │
│                                              │
│ ┌─ AI 翻译 ────────────────────────────────┐ │
│ │ 原始文件、服务商、Key、模型、语言          │ │
│ │                              [开始翻译]   │ │
│ │                                          │ │
│ │ 完成后在这里显示统计结果和输出路径          │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

AI 翻译不使用 Modal。建议使用一个直接显示在三个按钮下方的 `Card`，避免长时间任务被模态窗口包裹。

### 10.2 翻译前

AI 组件只显示执行流程需要的配置：

- 选择原始 JSON
- 原始文件完整路径
- 服务商：OpenAI、DeepSeek、Kimi、自定义
- API 地址：预设自动填写并可修正，自定义时由用户输入
- API Key
- 模型
- 源语言
- 目标语言
- 测试连接
- 开始翻译

选择原始 JSON 后，后台自动检查同目录工作文件，不要求用户另外选择工作文件。

如果不存在工作文件，按钮显示“开始翻译”。如果检测到工作文件，只显示一条简短提示：

```text
检测到未完成的翻译进度，将自动继续。
```

此时按钮显示“继续翻译”。翻译开始前不需要展示总条目、各状态数量、预计批次或其他统计信息。

推荐使用的 Ant Design 组件：

- 外层容器：`Card`
- 配置：`Form`
- 服务商、模型和语言：`Select`
- API 地址：`Input`
- API Key：`Input.Password`
- 文件选择：`Button` 加只读 `Input`
- 连接结果：简短的 `Alert` 或 `Tag`

文件选择继续使用 Electron 文件对话框，不使用 Ant Design `Upload`，因为文件不会上传到服务器。

### 10.3 翻译中

用户点击“开始翻译”或“继续翻译”后：

- 禁用 AI 组件的文件选择和全部配置。
- 禁止重复点击开始按钮。
- 不提供暂停、中止和修改配置功能。
- 使用 `Button loading` 或简单的 `Spin` 表示任务仍在执行。
- 不实时读取工作文件，也不展示批次、百分比、请求速度或实时状态数量。

界面只显示简单提示：

```text
正在翻译，请等待任务完成。
翻译结果会按批次保存到工作文件，请勿重复操作。
```

后台仍然按照既定逻辑，在每批结束后原子更新工作文件。界面是否实时展示与后台是否持续保存是两件独立的事。

React 侧只需要最少状态：

```ts
const [isTranslating, setIsTranslating] = useState(false);
const [result, setResult] = useState<TranslationSummary | null>(null);
const [errorMessage, setErrorMessage] = useState("");
```

### 10.4 翻译结束

批量请求结束后，由主进程重新读取工作文件并统计：

- `translated`
- `skipped`
- `error`
- `untranslated`

界面此时才展示最终情况，不需要保存和维护实时统计。

全部完成时，在 AI 组件内使用简洁的 `Alert` 显示：

```text
AI 翻译已完成

已翻译：14320
已跳过：352
错误：0
未翻译：0

输出文件：
D:\Game\CatToolTranslate.ai-translated.json

请点击上方“加载翻译文件”，重新选择该文件。
```

可以额外提供“打开文件所在目录”按钮，但不自动加载翻译文件，也不在 AI 组件里复制一套加载逻辑。

如果存在 `error` 或 `untranslated`，显示本次处理已经结束但仍有未完成内容。按钮重新启用并显示“继续翻译”；再次点击时，后台自然筛选未完成项目，不另外增加“重试失败项”按钮。

第一版不使用：

- Modal
- 内层 Tabs 或 Segmented
- Steps
- 大型翻译明细 Table
- 实时进度和用量图表
- 暂停或中止按钮
- 自动加载最终翻译文件

第一版也不提供费用估算、自动语言识别、自定义提示词、术语表、游戏背景、文本分类或复杂任务管理。

## 11. 实现结构

建议新增：

```text
src/
├─ electron/ai/
│  ├─ providerConfig.js    服务商、官方地址与模型预设
│  ├─ translator.js        请求、分批、校验与重试
│  ├─ workFile.js          工作文件创建、增量合并与最终导出
│  └─ aiIpc.js             专用 IPC
├─ types/AITranslation.ts  配置与最终结果类型
└─ ui/AITranslation/       TranslateTool 内的 AI 翻译组件
```

主进程负责读取原始 JSON、匹配和保存工作文件、导出最终 JSON、持有 API Key、发送网络请求，并在任务结束后返回最终统计。渲染进程只负责选择配置、显示等待状态和展示最终结果。

## 13. 第一版验收标准

- 用户能够选择服务商、填写或修改 URL、输入 Key、选择测试模型和语言。
- API Key 只存在于运行时内存，不出现在日志和磁盘文件中。
- 输入 JSON 中已有译文不会被覆盖或重复发送。
- 再次选择原始 JSON 时，工作文件中 `translated` 和 `skipped` 的项目不会被重置或覆盖。
- 原始 JSON 新增或删除 key 后，工作文件能够正确增量合并。
- 数万条文本能够自动分批，不会一次全部提交。
- AI 修改 key、漏项或返回非法 JSON 时不会错误写入结果。
- AI 判断无需翻译的项目即使 value 与 key 相同，也会标记为 `skipped` 且不再发送。
- 每完成一批都会更新工作 JSON。
- CTool 中途关闭后，重新选择原始 JSON 可以自动加载工作文件继续翻译。
- 翻译执行期间配置和开始按钮保持禁用，用户不能重复发起任务或中途修改配置。
- 完成的 JSON 可以直接用于现有实时加载和内嵌翻译功能。
- 完成后明确提示文件路径，由用户自行重新选择加载。
- 第一版不包含费用估算、自动语言识别和自定义提示词。

## 14. 第一版最终范围

第一版以 OpenAI 和 DeepSeek 为正式接入范围，默认模型预设为 `gpt-5.6-luna` 与 `deepseek-v4-flash`。Kimi 和自定义服务商入口暂不开放。

工作文件和最终文件均与用户选择的原始 JSON 放在同一目录。后续根据实际用户反馈继续调整模型预设、批次大小和服务商支持，不在第一版继续扩大范围。
